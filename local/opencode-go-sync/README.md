# OpenCode Go catalog sync kit (local)

This directory versions the **local-only** sync kit that drives the OpenCode Go
catalog overlay in this fork. It is not part of upstream
[`raine/claude-code-proxy`](https://github.com/raine/claude-code-proxy), and it
is never pushed there.

The kit lives in version control here, but the serve hook still reads it from
its default location (`~/.local/share/claude-code-proxy-sync`) or from
`CCP_SYNC_KIT`. Keep the two in sync with the `just` recipes below.

## What it does

1. Fetches the live OpenCode Go model list and endpoint documentation.
2. Applies the hand-maintained `overrides.toml` (exclusions and pins).
3. Generates `src/providers/opencode/overlay_generated.rs` in the working copy.
4. When the generated catalog changes, or the installed binary does not match
   the catalog stamp, runs the gates (`cargo fmt --check`, the kit self-test,
   focused catalog tests), builds release, and atomically installs
   `~/.local/bin/claude-code-proxy`.
5. Records `~/.local/bin/claude-code-proxy.catalog-sha256` so a stale binary
   cannot hide behind an unchanged catalog.

## Layout

| Path | Purpose |
| --- | --- |
| `sync.py` | Generator, fetch layer, gated install, stale-binary recovery |
| `tests/` | Offline fixture suite (`python3 sync.py --self-test`) |
| `fixtures/` | Live list, docs table, and roster snapshots |
| `overrides.toml` | Hand-maintained exclude/pin master |
| `patches/` | The two patches that add the overlay seam and serve hook |
| `bootstrap.sh` | One-command provisioning on a fresh machine |
| `pin-candidates.log` | Reference list of live models the docs do not cover |

`patched-files.sha256` is generated by `bootstrap.sh` and is intentionally not
committed: it records the local working copy's state and would go stale.

## Commands

The installed binary drives the sync directly:

```sh
# Normal sync: no-op when the catalog is current
claude-code-proxy sync

# Explicit rebuild: gate + build + install even when nothing changed
claude-code-proxy sync --force

# Inspect without writing, building, or installing
claude-code-proxy sync --dry-run

# Regenerate the catalog only
claude-code-proxy sync --no-install
```

`claude-code-proxy sync --force` is the command to use after pulling upstream
Rust changes or editing the proxy, because those do not change the catalog
overlay and would otherwise leave the installed binary untouched. The binary
still resolves the script and working copy through `CCP_SYNC_SCRIPT`,
`CCP_SYNC_REPO`, and `CCP_SYNC_KIT`, exactly like the serve hook.

The kit deployment recipes remain available for maintaining this versioned copy:

```sh
# Copy the versioned kit into the serve hook's default location
just sync-kit-install

# Copy the live kit back into the versioned directory after editing it in place
just sync-kit-capture
```

## Updating this copy

The live kit is the one that runs. Pick one direction and keep it explicit:

- Editing here: run `just sync-kit-install` to deploy the versioned copy.
- Editing the live kit in place: run `just sync-kit-capture` to copy it back
  here (it strips `__pycache__` and the generated `patched-files.sha256`).

Then commit the result on `jj/opencode-go-catalog-sync` and push to the `fork`
remote (never `origin`).
